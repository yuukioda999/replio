## 1. プロジェクトの目的と意思決定の経緯

### 1.1 企画
- サービス名: **Replio（レプリオ）**
- コンセプト: 受信したメールやチャットの文章を貼り付け、返信したい内容を補足すると、媒体・文体に合わせた返信文の下書きをAIが生成し、編集・コピーできるWebサービス。
- 想定利用: フリーランスエンジニアの顧客対応、SNS運用代行、小規模事業者、メール・Slack・ビジネスチャット。
- 解決したい課題: 返信文を考える手間、失礼な表現への不安、納期・仕様・金額の不用意な確約。
- 代替サービス: ChatGPT、Claude、メールサービスのAI、テンプレート、手作業。競合不在を主張しない。

### 1.2 最重要の目的変更
- 初期の事業計画では「顧客ヒアリング→Go/Pivot/Stop→Goなら開発」という順序を重視していた。
- 2026-10-14、ユーザーが「**本来はポートフォリオのためなので悩んでいるより実装しちゃった方が良くない？**」「**本来の目的覚えている？**」と確認。
- 以後の正しい方針: **ポートフォリオ制作を主軸として実装を進め、需要検証・集客・事業化は並行する。**
- ポートフォリオでは「AIを使った」という主張だけでなく、**要件・設計判断・テスト・運用・ユーザーの反応・改善**まで実証する。

### 1.3 事業化の仮説（確定売上ではない）
- 初期目標: **月商5万円**。
- 価格の仮説: Free / Lite **480円** / Standard **980円**（税込/税抜、機能、回数は未確定）。
- 有料化の前に支払意思・利用頻度・AI API原価を確認する。
- Xでの返信・顧客接触、アンケート、LPからの反応確認を行う。
- 2026-10-14にXで**10件リプライを実施した**とユーザーが報告。

### 2.1 責務分離の方向性
- **Handler:** HTTPの入出力、JSONデコード、基本的な入力検証、HTTPステータス変換。
- **Application / UseCase:** 返信生成ユースケース、プロンプト構築、未確定事項の扱い、LLMポートを介した呼び出し。
- **Infrastructure:** Claude等の外部LLM APIクライアント、ネットワーク、環境設定。
- **Fake:** 実APIキーや費用を使わず、UseCaseの正常系・異常系をテスト。
- **注意:** 上記は合意した層構成を具体化した整理であり、細かいディレクトリ名・interface名・DTO名までは本資料だけで確定しない。

### 2.2 安全な返信文
- 未確認の**納期、料金、仕様、対応可否**を勝手に確約しない。
- 第一候補は**プロンプト制御＋送信前の注意書き**。
- AI出力は下書きであり、送信前に利用者が確認する。
- 「絶対に誤確約しない」と保証しない。テストケースを用意して検証する。

## 4. ログインなしの無料利用・API費用の議論

### 4.1 ユーザーの問題提起
> 「ログインなしだと無料で使えちゃう？」

- **その通り。** 認証なしで生成APIを公開し、制限がなければ誰でも使えて運営側にLLM API費用が発生する。
- 認証がなくてもレート制限・利用量制御はできるが、匿名識別の回避は可能。

### 4.2 直近アシスタントの提案（**未合意・未確定**）
- 無料: **1日3回**（IPや匿名セッション等で制限）
- 月間API予算: **1,000円**
- Bot対策、CAPTCHA、入力文字数・生成トークン上限
- API使用量計測とサーバー側停止機構
- 将来案: Free 3回/日、Lite 480円で100回/月、Standard 980円で300回/月

**これらの具体的数値はアシスタントが提案したものであり、ユーザーが承認した事実はない。次のセッションで『決定済み』と扱わない。**

### 4.3 未解決の設計判断
- 認証なし公開の許容リスク
- 1ユーザー/1IP/1セッションあたりの上限
- IP変更・Cookie削除・共有IPへの対処
- レート制限状態の保存先（DBなし方針との整合、単一VPSのメモリ/Redis等）
- リバースプロキシ配下での信頼できるクライアントIP取得
- CAPTCHAの必要性
- API費用の上限と実際の停止手段
- LLM API障害時の表示と再試行
- ユーザー入力・ログの機密情報対策
