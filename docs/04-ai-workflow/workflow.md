# AI駆動・事業運営ワークフロー v0.1

## 原則

AIは調査・草案・実装・分析を支援する。**事実認定、顧客接触、要件確定、マージ、本番反映、支出、個人情報の扱いは人間が責任を持つ。**

## Stage gates

| ステージ | AIの担当 | 人間の検証 | GitHub証拠 |
| --- | --- | --- | --- |
| 市場調査 | 競合候補・比較軸・質問案 | 一次URL・顧客発言・価格の確認 | competitors.md、Issue |
| 顧客検証 | LP文案・インタビュー要約 | 本人の同意・匿名化・支払意思の判定 | validation.md、Go/Pivot/Stop ADR |
| 要件定義 | PRD・ストーリー・受入基準の草案 | スコープと優先順位の決定 | docs/02-product、Issue |
| 設計 | 選択肢、脅威、コストの比較 | ADR採否とリスク受容 | docs/03-architecture/adr |
| 実装 | 小単位のコード・テスト生成 | 差分レビュー、動作確認、マージ | PR、CIログ |
| QA | 境界値・攻撃パターン提案 | 実テスト実行、結果評価 | テスト、CI、Issue |
| 公開 | デプロイ手順・Runbook草案 | 権限、秘密情報、切り戻し確認 | リリース記録 |
| 集客 | 投稿・LP・営業文の草案 | 誇大表現、相手の同意、配信判断 | 施策Issue、集計値 |
| 運用 | エラー分類・改善仮説 | 原因確認、優先順位、修正 | 障害記録、改善PR |

## 1 Issue → 1 PR の標準フロー（実装開始後）

1. Issue: 背景、ユーザー価値、受入基準、非対象、計測方法を記載。
2. AI: 実装計画を提案。代替案とリスクを列挙。
3. Human: 計画を承認・修正。設計判断はADRに記録。
4. AI: 最小差分を実装し、単体・統合テストを追加。
5. CI: lint / typecheck / tests / secret scan（導入後）を実行。
6. Human: セキュリティ、コスト、保守性、境界条件、差分をレビュー。
7. PR: 検証方法・結果・未解決事項・ロールバックを記載。
8. Merge後: 必要な計測・運用情報を追記。

## AI利用記録（IssueまたはPRに残す）

- 利用ツール・モデル（分かる範囲）と目的
- 入力した課題の要約（秘密情報・顧客データを含めない）
- AIの提案内容、採用・不採用と理由
- 人間が発見した問題と修正
- テスト・計測の実測結果
- 次回改善するプロンプト・手順

## 安全・品質ルール

- APIキー、認証情報、顧客の原文、個人情報を外部AIへ無断送信しない。
- 調査結果は一次ソースを確認し、URL・確認日を残す。
- AIの生成コードを無審査でmainへマージしない。
- 認証/認可、テナント分離、ログへの情報漏洩、プロンプトインジェクションを検討。
- AI APIのタイムアウト、レート制限、コスト上限、異常時の停止方法を設計。
- 数字は計測条件と母数を添える。実績を創作しない。

## 評価・改善

開発速度だけでなく、AI提案の修正率、PRレビューでの発見、テスト失敗、障害、API原価、顧客の継続利用を記録する。比較できるデータが揃うまでは「AIで生産性が何倍」と主張しない。
